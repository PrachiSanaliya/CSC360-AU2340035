## Tree Data Structure

A tree is a data structure used to represent elements in a hierarchical structure.

The relationship between elements in a tree is represented using **parent nodes and child nodes**.

- A **parent node** is a node that has one or more child nodes.
- A **child node** is a node that comes under another node.
- A node can have multiple children.
- The parent-child relationship represents the hierarchy between the elements.

A tree can be represented in different orientations, including:

- Vertical
- Horizontal

The same parent-child relationship can be represented in either orientation depending on how the structure is displayed.

## Parent-Child Relationship in Project Structure

The parent-child relationship can also be seen in the structure of a software project.

For example:

```text
Project
│
├── src
│   └── main
│       └── java
│
├── target
│
├── pom.xml
└── .gitignore
```

Here, the project acts as the higher-level element, while the folders and files inside it form the child elements.

This gives a hierarchical structure similar to a tree.

## `/` and `\` in Paths

The use of `/` and `\` in file paths was discussed.

The `/` symbol is commonly used to show a directory hierarchy.

For example:

```text
src/main/java
```

represents:

```text
src
  ↓
main
  ↓
java
```

The `\` symbol is also used in Windows paths.

For example:

```text
C:\Users\prach\CSC360-AU2340035
```

Therefore, the symbols are used to represent movement through directories and the structure of files and folders.

## Target Folder

The `/target` folder is part of the Maven project structure.

Maven generates files and directories inside `target` during the build process.

The target folder can contain generated files such as compiled classes and other build-related files.

Because these files are generated by Maven, they generally do not need to be tracked as source files in the Git repository.

## .gitignore

`.gitignore` is used to specify files and folders that Git should not track.

For example:

```text
target/
```

can be included in `.gitignore` so that the generated Maven `target` folder is excluded from the Git repository.

This is useful for excluding generated files and IDE-specific files that are not part of the actual source code.

├── pom.xml
│

- `src/main/java` contains the main Java source code.
- `src/test/java` contains test code.

- `target` contains files generated during the Maven build process.

## Process and Thread in Operating System

The concepts of **process** and **thread** were discussed.

A **process** is a running program with its own execution environment.

A **thread** is a unit of execution within a process.

A single process can contain multiple threads.

The relationship can be represented as:

```text
Process
│
├── Thread 1
├── Thread 2
└── Thread 3
```

Threads within the same process can work concurrently and can share resources belonging to that process.

## Difference Between Process and Thread

The main difference discussed was the level at which they operate.

- A process represents a running program.
- A thread represents an execution path within a process.
- A process can contain multiple threads.
- Threads within a process can share resources.

This makes threads useful when different tasks need to be executed within the same application.

## Why Do We Need to Create Threads?

A thread is useful when an application needs to perform more than one task without making one task wait unnecessarily for another.

For example, in a graphical application, one task may involve displaying the interface while another task performs some computation.

Using separate threads can allow these tasks to proceed without blocking each other.

The purpose is therefore not simply to create multiple processes, but to allow different tasks within a process to execute concurrently.

## Multiple Processes and Threads

If an application does not need multiple tasks to execute concurrently, creating additional threads may not be necessary.

Threads become useful when there are multiple tasks that can be performed concurrently.

Therefore:

```text
One simple task
      ↓
One thread may be sufficient

Multiple concurrent tasks
      ↓
Multiple threads may be useful
```

The need for threads depends on what the program is required to do.

## GUI Interface and GUI Freezing

The relationship between threads and graphical user interfaces was discussed.

A GUI needs to remain responsive while other work is being performed.

If a long-running operation blocks the GUI's execution, the interface may stop responding.

This is referred to as **GUI freezing**.

For example:

```text
GUI
 ↓
Long-running operation
 ↓
GUI cannot respond
 ↓
GUI freezes
```

Using appropriate threads can allow the GUI to remain responsive while another task is being performed.

## Thread Safety

**Thread safety** was discussed in relation to multiple threads accessing shared resources.

A program or operation is thread safe when it can be used by multiple threads without causing incorrect results or inconsistent data.

Problems can occur when multiple threads access and modify the same resource at the same time.

For example:

```text
Thread 1 → reads file
Thread 2 → reads file
```

Reading the same file at the same time may not necessarily cause a problem.

However:

```text
Thread 1 → updates file
Thread 2 → updates file
```

can create a problem if both threads modify the same file simultaneously.

## Multitasking and File Corruption

When multiple threads perform operations on shared resources at the same time, the operations may interfere with each other.

For example, if two threads are simultaneously updating the same file, the resulting data may not be what either thread intended.

This can lead to issues such as **file corruption** or inconsistent data.

Therefore, shared resources need to be handled carefully when multiple threads are involved.

## Thread-Safe and Thread-Unsafe Packages

It was discussed that some Java packages or classes are not thread safe.

This means that they may not be designed to safely handle simultaneous access from multiple threads without additional control.

Thread safety therefore needs to be considered when selecting and using classes in a multithreaded program.

## Why Are Some Things Thread Unsafe?

Making every operation thread safe can introduce additional synchronization and coordination.

When a resource is shared, threads may need to wait for one another to access or modify it safely.

Therefore, not every operation is automatically made thread safe.

The programmer needs to consider whether an operation or resource will be accessed by multiple threads and whether synchronization is required.

## Multiple Threads While Drawing

The possibility of using multiple threads while drawing something was also discussed.

Graphics applications can involve multiple operations, but using multiple threads with shared graphical resources requires care.

If multiple threads access or modify the same resource without proper control, thread-safety problems can occur.

Therefore, the use of multiple threads in a graphics application needs to consider which parts of the drawing process and resources are being shared.
